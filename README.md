# Dynamic Private Proof of Assets Prototype

This repository is a Rust workspace for experimenting with dynamic private
proof-of-assets protocols.  It contains two implementations:

- `nizk-fixed-set`: algebraic fixed-set NIZK using masked set polynomials,
  KZG commitments, Pedersen commitments, committed-R1CS Bulletproofs, and
  external link proofs.
- `smt` / `sp1-host`: a local sparse-Merkle-tree route with SP1-style host and
  guest program layout.

The GitHub repository may only contain `crates/` and `vendor/`.  All runtime
folders, SRS files, CSV inputs, states, proofs, reports, and benchmark outputs
are created locally by the user.

## 1. Environment

Install Rust stable:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup default stable
```

Build the CLI:

```bash
cargo build --release -p poa-cli
```

All examples below run from the repository root.  You can use either form:

```bash
cargo run --release -p poa-cli -- <command> ...
target/release/poa-cli <command> ...
```

The second form is faster after the first release build.

## 2. Local Directory Layout

Create these local folders:

```bash
mkdir -p inputs outputs/srs outputs/states outputs/proofs outputs/reports outputs/mock outputs/bench
```

Recommended purpose:

```text
inputs/          hand-written CSV inputs
outputs/srs/     KZG SRS files
outputs/states/  generated protocol states
outputs/proofs/  generated init/update proofs
outputs/reports/ benchmark reports
outputs/mock/    mock-chain datasets generated by mock-gen
outputs/bench/   captured benchmark logs
```

Do not commit large generated files such as `outputs/srs/srs.bin`.

## 3. Input CSV Files

### Reserve CSV

Path used below:

```text
inputs/reserves.csv
```

Format:

```text
<ethereum-address>,<balance>
```

Example:

```bash
cat > inputs/reserves.csv <<'EOF'
0x1111111111111111111111111111111111111111,100
0x2222222222222222222222222222222222222222,250
EOF
```

`balance` is an integer used by the prototype.  The current initialization path
uses mock ownership and mock chain-balance artifacts for benchmarking.

### Delta CSV

Path used below:

```text
inputs/deltas.csv
```

Format:

```text
<ethereum-address>,<signed-delta>
```

Example:

```bash
cat > inputs/deltas.csv <<'EOF'
0x1111111111111111111111111111111111111111,-10
0x3333333333333333333333333333333333333333,40
EOF
```

The reader normalizes addresses, sorts entries, merges duplicate address
deltas, and drops zero deltas.

### Mock-Owned Init CSV

Only needed for `init-mock-owned`:

```text
<ethereum-address>,<balance>,<mock-private-key>
```

Example:

```bash
cat > inputs/init_witness.csv <<'EOF'
0x1111111111111111111111111111111111111111,100,key-1
0x2222222222222222222222222222222222222222,250,key-2
EOF
```

## 4. KZG SRS

The fixed-set NIZK needs a powers-of-tau SRS.

Generate a small local SRS:

```bash
target/release/poa-cli gen-srs 256 outputs/srs/srs_256.bin
```

Generate a large experimental SRS for `n = 10^6`:

```bash
target/release/poa-cli gen-srs 1000000 outputs/srs/srs.bin
```

Parameters:

```text
gen-srs <max-degree> <srs.bin>
```

- `max-degree`: highest polynomial degree supported by the SRS.
- `srs.bin`: output path for the binary SRS.

The generated SRS is deterministic and for experiments only.  It is not a
production trusted setup ceremony.

If you already downloaded an SRS, put it under `outputs/srs/` and pass that
path to the commands.  The current binary format is:

```text
u64 max_degree
u64 g1_len
g1_len compressed arkworks BLS12-381 G1Affine points
u64 g2_len
g2_len compressed arkworks BLS12-381 G2Affine points
```

The file must contain powers:

```text
[1]_1, [tau]_1, ..., [tau^D]_1
[1]_2, [tau]_2, ..., [tau^D]_2
```

Generic `.ptau`, Ethereum KZG JSON, Lagrange-form SRS, or G1-only files must be
converted before this CLI can read them.

## 5. Serial Fixed-Set NIZK Flow

This route treats the reserve set as fixed.  It commits to a masked set
polynomial and proves updates from public address deltas.

### 5.1 Initialize

```bash
target/release/poa-cli init \
  outputs/srs/srs_256.bin \
  inputs/reserves.csv \
  root-0 \
  outputs/states/nizk_state0.txt \
  outputs/proofs/nizk_init_proof.txt
```

Parameters:

```text
init <srs.bin> <reserves.csv> <state-root> <state.txt> <init-proof.txt>
```

- `srs.bin`: KZG SRS path.
- `reserves.csv`: private reserve list used by the prover.
- `state-root`: public chain/root label for this initial state.
- `state.txt`: output state file.
- `init-proof.txt`: output initialization proof file.

### 5.2 Update

```bash
target/release/poa-cli update \
  outputs/srs/srs_256.bin \
  outputs/states/nizk_state0.txt \
  inputs/deltas.csv \
  root-1 \
  outputs/states/nizk_state1.txt \
  outputs/proofs/nizk_update_proof1.txt
```

Parameters:

```text
update <srs.bin> <state.txt> <deltas.csv> <new-state-root> <next-state.txt> <proof.txt>
```

- `state.txt`: previous accepted state.
- `deltas.csv`: public canonical address-delta list.
- `new-state-root`: public root label after applying deltas.
- `next-state.txt`: output next state.
- `proof.txt`: output update proof.

### 5.3 Verify

```bash
target/release/poa-cli verify \
  outputs/srs/srs_256.bin \
  outputs/states/nizk_state0.txt \
  inputs/deltas.csv \
  outputs/states/nizk_state1.txt \
  outputs/proofs/nizk_update_proof1.txt \
  outputs/proofs/nizk_init_proof.txt
```

Parameters:

```text
verify <srs.bin> <old-state.txt> <deltas.csv> <new-state.txt> <proof.txt> <init-proof.txt>
```

The verifier checks the initialization proof, KZG opening, Bulletproof relation,
link proof, and homomorphic balance commitment transition.

## 6. Parallel Fixed-Set NIZK Flow

The parallel route shards the fixed reserve set into `t` smaller masked set
polynomials.  Each shard proves the local zero-test relation.  The verifier
batch-checks all shard KZG openings with one randomized pairing equation.  The
coordinator creates one global projection proof for:

```text
d = <u, delta>
```

where `u` is the sum of the shard membership vectors.

### 6.1 Initialize Sharded State

```bash
target/release/poa-cli parallel-init \
  outputs/srs/srs_256.bin \
  inputs/reserves.csv \
  root-0 \
  4 \
  outputs/states/parallel_state0.txt \
  outputs/proofs/parallel_init_proof.txt
```

Parameters:

```text
parallel-init <srs.bin> <reserves.csv> <state-root> <shards> <state.txt> <init-proof.txt>
```

- `shards`: number of shard polynomials/workers.
- Other paths have the same meaning as serial `init`.

### 6.2 Parallel Update

```bash
target/release/poa-cli parallel-update \
  outputs/srs/srs_256.bin \
  outputs/states/parallel_state0.txt \
  inputs/deltas.csv \
  root-1 \
  outputs/states/parallel_state1.txt \
  outputs/proofs/parallel_update_proof1.txt
```

Parameters:

```text
parallel-update <srs.bin> <state.txt> <deltas.csv> <new-state-root> <next-state.txt> <proof.txt>
```

The proof file contains shard-local zero-test proofs and one global projection
proof.

### 6.3 Parallel Verify

```bash
target/release/poa-cli parallel-verify \
  outputs/srs/srs_256.bin \
  outputs/states/parallel_state0.txt \
  inputs/deltas.csv \
  outputs/states/parallel_state1.txt \
  outputs/proofs/parallel_update_proof1.txt \
  outputs/proofs/parallel_init_proof.txt
```

Parameters:

```text
parallel-verify <srs.bin> <old-state.txt> <deltas.csv> <new-state.txt> <proof.txt> <init-proof.txt>
```

## 7. NIZK Performance Benchmarks

### 7.1 Serial Synthetic Benchmark

This avoids creating a million-address CSV.  It creates a synthetic degree-`n`
polynomial and updates it at `m` public addresses.

```bash
target/release/poa-cli synthetic-update-bench outputs/srs/srs.bin 1000000 1000
```

Parameters:

```text
synthetic-update-bench <srs.bin> <degree> <modified-addresses>
```

- `degree`: polynomial degree, used as the synthetic set size `n`.
- `modified-addresses`: delta-list size `m`.

### 7.2 Parallel Synthetic Benchmark

```bash
target/release/poa-cli parallel-synthetic-update-bench outputs/srs/srs.bin 1000000 1000 8
```

Parameters:

```text
parallel-synthetic-update-bench <srs.bin> <degree> <modified-addresses> <shards>
```

- `degree`: total synthetic degree across shards.
- `modified-addresses`: delta-list size `m`.
- `shards`: number of shard polynomials.

Compare shard counts:

```bash
for s in 1 2 4 8 16; do
  echo "== shards=$s =="
  target/release/poa-cli parallel-synthetic-update-bench outputs/srs/srs.bin 1000000 1000 "$s"
done
```

Save benchmark output:

```bash
target/release/poa-cli parallel-synthetic-update-bench outputs/srs/srs.bin 1000000 1000 8 \
  2>&1 | tee outputs/bench/nizk_parallel_n1e6_m1e3_s8.txt
```

Important output fields:

```text
state_build_millis      time to build synthetic state and commitments
update_millis           prover update time
verify_millis           verifier time
zero_test_gate_count    total shard zero-test gates
projection_gate_count   single global projection size
```

## 9. SMT Route

The SMT route maintains a local salted sparse Merkle tree of hidden reserve
addresses.  It is separate from the algebraic fixed-set NIZK route.

Prepare SP1-style setup artifacts:

```bash
target/release/poa-cli sp1-setup
```

This creates `.sp1-setup/` by default.  You can also pass a custom setup
directory:

```bash
target/release/poa-cli sp1-setup outputs/sp1-setup
```

Initialize an SMT state:

```bash
target/release/poa-cli smt-init \
  32 \
  inputs/reserves.csv \
  root-0 \
  outputs/states/smt_state0.txt
```

Parameters:

```text
smt-init <depth> <reserves.csv> <state-root> <state.txt>
```

Apply an SMT update:

```bash
target/release/poa-cli smt-update \
  outputs/states/smt_state0.txt \
  inputs/deltas.csv \
  root-1 \
  outputs/states/smt_state1.txt \
  outputs/proofs/smt_update_proof1.txt
```

Verify:

```bash
target/release/poa-cli smt-verify \
  outputs/states/smt_state0.txt \
  outputs/states/smt_state1.txt \
  outputs/proofs/smt_update_proof1.txt \
  update
```

Insert a new reserve leaf:

```bash
target/release/poa-cli smt-insert \
  outputs/states/smt_state1.txt \
  0x3333333333333333333333333333333333333333 \
  40 \
  root-2 \
  outputs/states/smt_state2.txt \
  outputs/proofs/smt_insert_proof2.txt
```

Verify insertion:

```bash
target/release/poa-cli smt-verify \
  outputs/states/smt_state1.txt \
  outputs/states/smt_state2.txt \
  outputs/proofs/smt_insert_proof2.txt \
  insert
```

SMT synthetic benchmark:

```bash
target/release/poa-cli smt-synthetic-bench 32 10000 1000
```

Parameters:

```text
smt-synthetic-bench <depth> <num-reserves> <modified-addresses>
```

## 11. Troubleshooting

### `No such file or directory`

Create the local folders first:

```bash
mkdir -p inputs outputs/srs outputs/states outputs/proofs outputs/reports outputs/mock outputs/bench
```

### SRS read errors

If a command fails with `read srs ...`, the SRS file is missing, too small, or
in the wrong format.  Generate a fresh experimental SRS:

```bash
target/release/poa-cli gen-srs 1000000 outputs/srs/srs.bin
```

### SRS degree too small

For serial fixed-set NIZK:

```text
max_degree >= max(set_polynomial_degree, delta_list_size)
```

For parallel fixed-set NIZK with `t` shards:

```text
max_degree >= max(max_shard_degree, delta_list_size)
```

### Slow first run

The first `cargo run --release` may compile many dependencies.  Build once:

```bash
cargo build --release -p poa-cli
```

Then use:

```bash
target/release/poa-cli <command> ...
```

### Existing old state/proof files fail verification

State and proof formats changed while the prototype evolved.  Regenerate
states and proofs with the current CLI instead of mixing old local artifacts
with new code.

### GitHub repository has only `crates/` and `vendor/`

That is expected.  Create `inputs/`, `outputs/`, and `.sp1-setup/` locally as
described above.  They are runtime artifacts, not source folders.
